## 1. 제품 요약

Career Radar는 사용자의 경력 목표와 제약 조건을 기준으로 채용공고를 수집·정규화·평가하고, 적합도 근거와 반복적으로 요구되는 역량을 모바일 웹에서 보여주는 개인용 구직 도구임.

MVP는 다음 루프를 완성함.

1. **Setup** — Tally 또는 Typeform으로 프로필 입력
2. **Collect** — 고용24 Open API 수집 및 공고 본문 직접 붙여넣기
3. **Rank** — Gemini 구조화 추출 후 Python 규칙으로 필터링·점수 계산
4. **Prepare** — 사용자가 선택한 공고에 한해 지원 준비 자료 생성
5. **Track** — 저장, 준비 완료, 지원, 면접 등 상태 기록

## 2. 배경과 문제

구직자는 여러 채용 사이트를 반복해서 확인하고, 공고마다 경력·고용형태·기술 요구사항을 수작업으로 비교해야 함. LLM만으로 공고를 평가하면 결과가 매번 달라질 수 있고, 점수 근거도 불투명해짐. 지원 현황과 반복적으로 부족한 기술을 별도로 관리하는 부담도 큼.

Career Radar는 이 문제를 다음 방식으로 해결함.

- 원문 공고와 추출 결과를 분리해 보관함.
- Gemini는 비정형 문장을 구조화하고 설명을 작성하는 데 사용함.
- 필수 제외 조건과 최종 점수는 재현 가능한 Python 규칙으로 계산함.
- 비용이 큰 생성 작업은 사용자가 `지원 준비`를 누른 경우에만 실행함.
- 실제 지원 제출은 사용자가 직접 수행함.

## 3. 목표 사용자

### 3.1 MVP 사용자

초기 버전은 단일 사용자 데모를 대상으로 함.

- 목표 직무: Python Backend / AI Data & Agent Workflow Tooling Engineer
- 경력 범위: 신입~3년
- 선호 지역: 서울 전체, 송파·강남 우선
- 근무 형태: 하이브리드 선호, 해외 원격 허용
- 제외 조건: 5년 이상 요구, 계약직, 파견, 상주 인력 형태

### 3.2 향후 사용자

자신의 목표 직무, 경력, 지역, 고용형태, 기술 스택을 입력하고 개인화된 공고 우선순위를 원하는 구직자.

## 4. 제품 원칙

- **근거 우선:** 모든 평가에는 공고 원문의 근거 문구를 연결함.
- **결정론적 점수:** 동일한 프로필과 동일한 공고는 동일한 점수를 반환함.
- **사람이 최종 결정:** 자동 지원이나 외부 사이트 제출을 수행하지 않음.
- **저비용 배치, 고비용 온디맨드:** 일일 수집·평가는 배치로 실행하고 지원자료 생성은 선택 공고에만 실행함.
- **모바일 우선:** 데모 핵심 흐름은 휴대전화 한 손 조작 기준으로 설계함.

## 5. 목표와 제외 범위

### 5.1 MVP 목표

- 외부 폼을 통한 후보자 프로필 등록
- 고용24 Open API 기반 일일 공고 수집
- 공고 본문 직접 붙여넣기
- URL, 외부 공고 ID, 본문 해시를 이용한 중복 제거
- 공고의 기술, 경력, 고용형태, 위치, 업무 내용을 구조화
- 필수 제외 조건 적용
- 설명 가능한 적합도 점수와 판정 제공
- 전체 공고에서 반복되는 기술 격차 집계
- 선택 공고의 지원 준비 브리프 생성
- 지원 상태 기록 및 간단한 파이프라인 현황 제공

### 5.2 MVP 제외 범위

- 사람인, 원티드, LinkedIn 등 웹사이트 직접 크롤링
- 외부 채용 사이트 로그인과 자동 지원
- 이력서·자기소개서 전체 문서 자동 작성
- 이메일 또는 캘린더 연동
- 기업 뉴스 및 심층 리서치
- 다중 사용자 인증과 조직 기능
- 실시간 푸시 알림
- 추천 모델 학습 및 벡터 검색 인프라

## 6. 핵심 사용자 흐름

### 6.1 프로필 설정

1. 사용자가 Tally 또는 Typeform 링크를 열음.
2. 목표 직무, 경력, 기술, 선호 지역, 근무 형태, 제외 조건을 입력함.
3. 폼 Webhook이 백엔드로 전달됨.
4. 백엔드가 입력을 검증하고 최신 프로필 버전을 저장함.
5. 모바일 웹에서 설정 완료 상태를 확인함.

### 6.2 예약 공고 수집

1. Cloud Scheduler가 하루 1회 수집 작업을 실행함.
2. 수집 작업이 고용24 Open API를 페이지 단위로 호출함.
3. 원본 응답을 Cloud Storage에 보관함.
4. 공고를 정규화하고 중복을 제거함.
5. 신규 또는 변경 공고만 분석 대상으로 전달함.
6. 구조화 추출과 규칙 점수 계산 후 모바일 피드에 노출함.

### 6.3 공고 직접 추가

1. 사용자가 공고 본문과 선택적인 URL을 붙여넣음.
2. 시스템이 본문 해시로 중복 여부를 확인함.
3. 신규 공고이면 정규화·평가함.
4. 완료 후 해당 공고 상세 화면으로 이동함.

### 6.4 공고 탐색과 평가 확인

1. 사용자가 적합도순 공고 피드를 확인함.
2. 제외 공고는 기본 피드에서 숨기되 필터로 확인할 수 있음.
3. 상세 화면에서 점수 구성, 매칭 기술, 부족 기술, 근거 문구를 확인함.
4. 공고를 저장하거나 `지원 준비`를 선택함.

### 6.5 지원 준비

1. 사용자가 특정 공고에서 `지원 준비`를 누름.
2. 시스템이 프로필과 공고 원문을 바탕으로 Application Brief를 생성함.
3. 사용자가 다음 항목을 확인하고 직접 수정·활용함.
   - 공고 핵심 요구사항
   - 강조할 경험과 기술
   - 부족한 근거 또는 확인할 질문
   - 자기소개서 작성용 개요
   - 면접 준비 질문
4. 시스템은 실제 지원 제출을 수행하지 않음.

### 6.6 지원 상태 추적

사용자는 공고 상태를 `저장`, `준비 중`, `준비 완료`, `지원`, `면접`, `오퍼`, `불합격`, `철회` 중 하나로 변경할 수 있음.

## 8. 모바일 웹 정보 구조

하단 내비게이션은 `공고`, `스킬 갭`, `지원 현황`, `설정`의 네 영역으로 구성함.

### 8.1 공고 피드

- 카드 정보: 회사, 직무명, 위치, 근무 형태, 마감일, 적합도, 판정
- 기본 정렬: 적합도 내림차순
- 필터: 전체, 저장, 지원 준비, 제외됨
- 주요 행동: 상세 보기, 저장, 직접 추가

### 8.2 공고 상세

- 전체 점수와 네 개 하위 점수
- 통과 또는 제외 사유
- 매칭 기술과 부족 기술
- 경력·고용형태·위치 분석
- 판단별 원문 근거
- 원문 링크
- `지원 준비` 버튼

### 8.3 스킬 갭

- 부족 기술별 공고 수
- 해당 기술을 요구하는 상위 공고
- 현재 프로필 기술과의 구분

### 8.4 지원 현황

- 상태별 공고 수
- 최근 상태 변경 내역
- 준비 완료 브리프 재열람

## 9. 필터와 점수 정책

### 9.1 필수 제외 조건

아래 조건 중 하나라도 명확하게 충족하면 기본 추천 피드에서 제외함.

- 최소 요구 경력이 5년 이상임
- 계약직, 파견직, 도급 또는 상주 인력 채용임
- 공고가 마감 또는 삭제됨

근거가 불명확하면 자동 제외하지 않고 `확인 필요`로 표시함.

### 9.2 적합도 점수

필수 제외 조건을 통과한 공고에 대해 0~100점으로 계산함.

| 항목 | 가중치 | 평가 내용 |
|---|---:|---|
| 기술 적합도 | 40% | 필수·우대 기술과 현재 기술의 일치 |
| 경력 적합도 | 25% | 요구 연차와 신입~3년 목표의 일치 |
| 직무 방향성 | 25% | Python Backend, AI Data, Agent Workflow 업무와의 일치 |
| 근무 선호 | 10% | 지역, 하이브리드, 해외 원격 선호의 일치 |

판정 구간은 다음과 같음.

| 점수 | 판정 |
|---:|---|
| 75~100 | Strong fit |
| 60~74 | Good fit |
| 45~59 | Moderate fit |
| 30~44 | Weak fit |
| 0~29 | Poor fit |

Gemini는 점수를 직접 결정하지 않음. Gemini가 구조화한 필드와 원문 근거를 입력으로 Python 점수 엔진이 계산함.

## 10. 성공 지표

### 10.1 품질

- 최소 20개 수동 라벨 공고에서 구조화 스키마 성공률 95% 이상
- 명시적인 필수 제외 공고 탐지율 100%
- 수동 평가 기준 상위 5개 추천의 적합 공고 비율 80% 이상
- 동일 입력 재평가 시 점수 일치율 100%
- 평가 상세의 핵심 판단에 근거 문구 제공률 90% 이상

### 10.2 운영

- 일일 수집 재실행 시 중복 레코드 0건
- 공고 피드 API p95 응답시간 3초 이하
- 단일 공고 지원 준비 p95 완료시간 30초 이하
- 실패한 공고가 전체 배치 완료를 막지 않음

### 10.3 데모

- 프로필 입력부터 추천 피드 확인까지 하나의 시나리오로 시연 가능
- 직접 붙여넣은 공고가 평가되어 상세 화면에 나타남
- 선택 공고의 Application Brief가 생성됨
- 상태 변경이 지원 현황에 반영됨

## 11. MVP 승인 기준

- 유효한 프로필 Webhook을 저장하고 잘못된 요청을 4xx로 거부함.
- 고용24 수집 작업이 신규 공고와 변경 공고를 구분함.
- 공고 원본, 정규화 결과, 평가 결과를 각각 조회할 수 있음.
- 필수 제외 규칙과 점수 단위 테스트가 통과함.
- 모바일 너비 360px에서 가로 스크롤 없이 핵심 화면을 사용할 수 있음.
- 공고 평가 실패 시 오류 상태와 재시도 가능한 정보가 남음.
- 지원 준비 결과가 공고와 프로필 버전에 연결되어 저장됨.
- 실제 외부 사이트 지원을 자동으로 수행하는 기능이 없음.

## 12. 위험과 대응

| 위험 | 영향 | 대응 |
|---|---|---|
| 고용24 API 승인 또는 응답 필드 차이 | 수집 데모 지연 | 저장된 샘플 응답과 직접 붙여넣기를 데모 폴백으로 준비함 |
| LLM 추출 오류 | 필터·점수 오류 | JSON 스키마 강제, 필드 검증, 근거 문구, 실패 격리 적용 |
| 공고 문구의 모호한 경력 조건 | 과도한 제외 | 불명확한 경우 `확인 필요`로 처리하고 자동 제외하지 않음 |
| BigQuery의 잦은 상태 수정 | 구현 복잡도 증가 | 지원 상태를 append-only 이벤트로 기록하고 최신 상태를 조회함 |
| 공개 데모의 개인정보 노출 | 보안·프라이버시 문제 | 합성 또는 최소화된 프로필만 사용하고 원본 이력서는 저장하지 않음 |
| 짧은 PBL 일정 | 핵심 흐름 미완성 | P0 흐름을 우선하고 알림·다중 사용자·자동 지원을 제외함 |

## 14. 3분 데모 시나리오

1. 모바일 홈에서 목표 직무와 최근 수집 시각을 보여줌.
2. 적합도 상위 공고를 열어 점수 구성과 원문 근거를 설명함.
3. 계약직 또는 5년 이상 공고가 규칙으로 제외된 사례를 보여줌.
4. 새 공고 본문을 붙여넣고 평가 결과를 확인함.
5. `지원 준비`를 눌러 Application Brief를 생성함.
6. 상태를 `지원`으로 바꾸고 지원 현황에 반영된 결과를 보여줌.
